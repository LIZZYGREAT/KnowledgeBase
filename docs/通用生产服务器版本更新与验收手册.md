# KnowledgeBase 生产服务器版本更新（简洁可靠版）

适用：`/srv/KnowledgeBase`、生产 `main`、单用户、Docker Compose。每次只需：**备份 → 合并远端 → 串行构建 → 更新容器 → 检查**。无须填写 SHA 或创建手工验收表。

> 逐步执行并检查结果，不用一整段 heredoc 执行更新。备份脚本已使用 `docker compose run ... -T`。如自动 Timer 已启用，先停 Timer；备份锁会等待当前检索结束。备份恢复旧 Web 服务后再次停止它们，避免后台手动队列在代码更新期间执行。

## 一、日常更新

**第 1 步：备份**（在 `agent` 终端）。备份脚本会暂时停止并恢复旧版 Web 服务，成功时输出 `Created /backups/knowledgebase-....tar.gz`。

```bash
cd /srv/KnowledgeBase
git status --short
./scripts/production-backup.sh
docker compose --env-file .env -f docker-compose.production.yml stop frontend backend
```

如果备份已成功且此次操作尚未变更代码、数据库，可直接从第 2 步继续，**不必再次备份**；先确认 Web 服务已停止。

**第 2 步：更新代码**。服务器有 Publisher 本地 Git 提交，必须合并，不能 `reset --hard`。升级期间不要在网页继续写入。

```bash
cd /srv/KnowledgeBase
git status --short
git pull --no-rebase origin main
```

如果出现 Git 冲突或未提交变更，停止后续操作，把 `git status` 和报错提交排查。

**第 3 步：串行构建**。两条命令逐条完成后继续，不做无关性能测试。

```bash
cd /srv/KnowledgeBase
docker compose --env-file .env -f docker-compose.production.yml build backend
docker compose --env-file .env -f docker-compose.production.yml build frontend
```

**第 4 步：启动新版本**。`--force-recreate` 确保新容器使用刚构建的镜像。

```bash
cd /srv/KnowledgeBase
docker compose --env-file .env -f docker-compose.production.yml up -d --no-build --force-recreate --wait --wait-timeout 180 backend frontend
```

**第 5 步：最小验收**。确认 `healthy`、索引和两个 HTTP 请求。

```bash
cd /srv/KnowledgeBase
docker compose --env-file .env -f docker-compose.production.yml exec -T backend python /workspace/tools/kb.py check
docker compose --env-file .env -f docker-compose.production.yml exec -T backend python /workspace/tools/kb.py rebuild
docker compose --env-file .env -f docker-compose.production.yml exec -T backend python /workspace/tools/research.py check --root /workspace
docker compose --env-file .env -f docker-compose.production.yml ps
curl --noproxy '*' -fsS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8080/
curl --noproxy '*' -fsS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8080/api/terms/candidates
```

两个 HTTP 请求应均返回 `200`，前后端为 `healthy`。若你的 `.env` 修改了 `KB_HTTP_PORT`，应使用实际端口。最后从浏览器查看**本次修改过的功能**即可。

Research Timer 保持更新前的关闭状态；不会自动启用定时发现。Backend 启动后会恢复已有手动请求，启用了 AI 分析的请求可能按既有授权调用 DeepSeek；验收前应查看队列和研究方向的 AI 开关。如当前 Timer/Service 正在运行，应先按实际情况停止 Timer、等待任务结束，再安排备份和升级。

## 二、失败时怎么处理

- **备份失败**：停止，不跳过备份；备份成功时无需反复备份。
- **Git 冲突**：保留现场，不运行 `reset --hard`、`rebase` 或强推。
- **构建失败**：不要启动混合版本容器；贴出构建错误。维护期间 Web 服务保持停止；不要直接用旧镜像配合已经更新的挂载代码重启。
- **容器不健康或网页无法访问**：执行以下两条，提供输出即可：

```bash
cd /srv/KnowledgeBase
docker compose --env-file .env -f docker-compose.production.yml ps
docker compose --env-file .env -f docker-compose.production.yml logs --tail=80 backend frontend
```
